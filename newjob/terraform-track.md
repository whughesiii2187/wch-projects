# Terraform Track: Relearning Terraform on Azure

Eight lessons, T1 to T8, alternating weekly with the Python track. Planned at roughly 6 hours per week. Run `terraform destroy` at the end of every session to keep Azure costs near zero.

| Week | Lesson |
|---|---|
| 2 | T1: Core workflow and what's changed |
| 4 | T2: Expressions and iteration |
| 6 | T3: Dependencies and lifecycle |
| 8 | T4: Modules |
| 9 | T5: Refactoring and state operations |
| 10 | T6: Testing and code quality |
| 11 | T7: CI/CD with OIDC |
| 12 | T8: Design at scale |

---

## How each lesson works

1. **Study.** Read the listed concepts in the official docs: developer.hashicorp.com/terraform, and the `azurerm` provider docs on the Terraform Registry.
2. **Explain it back.** Before writing any code, explain the "be able to explain" items to Claude in your own words. Expect follow-up questions.
3. **Build.** Attempt the exercise yourself.
4. **Review.** Bring your code and your `plan` output to Claude for a PR-style review.
5. **Checkpoint.** Ask Claude to "quiz me on T#" before moving on.

**When you're stuck, hints escalate in this order:** the concept you're missing, then the relevant doc section, then the approach described in plain English. A small snippet comes last, and only for the specific piece you're stuck on. There are no finished solutions.

**Learning log:** keep one file per lesson recording what confused you, what fixed it, and anything that surprised you.

## T1: Core workflow and what's changed

**Be able to explain:**
- What happens during `init`, `plan`, and `apply`.
- Providers, and how version constraints work.
- The purpose of the dependency lock file.
- Variables versus locals versus outputs.
- Why `azurerm` v4 requires `subscription_id`.
- What changed while you were away: the 2023 license change and the OpenTofu fork; `import`, `removed`, and `check` blocks; `terraform test`; and ephemeral values.

**Exercise:** configure a remote state backend on an Azure storage account, then deploy a resource group and a VNet.

**Done when:** you can explain where your state lives, how it's locked (blob leases), and what's inside it. Open the state file and read it.

**Log:** _

## T2: Expressions and iteration

**Be able to explain:**
- The type system: maps, objects, lists, and sets.
- `for_each` versus `count`, and the index-shifting problem.
- `dynamic` blocks, and when they hurt readability.
- Conditional expressions.
- The `cidrsubnet` function.

**Exercise:** drive subnets and NSG rules from a single map variable, with subnet CIDRs calculated rather than hardcoded.

**Done when:** adding or removing a subnet from the middle of the map affects only that subnet in the plan.

**Log:** _

---

## T3: Dependencies and lifecycle

**Be able to explain:**
- Implicit versus explicit dependencies.
- When `depends_on` is a code smell.
- The lifecycle arguments `create_before_destroy`, `prevent_destroy`, and `ignore_changes`, and what each one can break.

**Exercise:** build a storage account reachable only through a private endpoint, with private DNS resolving correctly inside the VNet.

**Done when:** it deploys cleanly from scratch in one apply and destroys cleanly too.

**Log:** _

---

## T4: Modules

**Be able to explain:**
- Root modules versus child modules.
- What belongs in a module's interface.
- Input validation.
- Referencing a module by Git tag.
- Semantic versioning for infrastructure.

**Exercise:** turn your network into a module in its own repo, consumed by tag from a separate repo, with docs generated by `terraform-docs`.

**Done when:** releasing v1.1.0 with a new optional input doesn't change the plan for a v1.0.0 consumer.

**Log:** _

---

## T5: Refactoring and state operations

**Be able to explain:**
- What `moved`, `import`, and `removed` blocks each do.
- When you'd still reach for the `terraform state` subcommands.
- How state locking works.
- When `force-unlock` is dangerous.

**Exercise:** four drills.
1. Rename a resource using a `moved` block.
2. Adopt a portal-created resource using an `import` block.
3. Delete your state file, then recover it from blob versioning.
4. Clear a stuck lock safely.

**Done when:** each drill ends with a plan that makes no unexpected changes.

**Log:** _

## T6: Testing and code quality

**Be able to explain:**
- What `terraform test` can and can't verify.
- Mock providers.
- `tflint` versus a security scanner (`trivy` or `checkov`), and what each catches that the others miss.

**Exercise:** add tests and linting to your T4 module.

**Done when:** a bad input and an insecure configuration each fail with a clear message.

**Log:** _

## T7: CI/CD with OIDC

**Be able to explain:**
- How OIDC federation works between GitHub and Entra ID.
- Scoping role assignments per environment.
- Plan on PR versus apply on merge.
- Why a saved plan can become stale before it's applied.

**Exercise:** build a GitHub Actions pipeline that runs checks and a plan on every PR, requires approval before applying to prod, and stores no secrets anywhere.

**Done when:** a direct push to main cannot bypass the checks.

**Log:** _

## T8: Design at scale

**Be able to explain:**
- Splitting state by blast radius and ownership.
- One repo versus many.
- Ways of sharing outputs between stacks, and the coupling each creates.
- Governing modules across teams.

**Exercise:** write an architecture decision record proposing a Terraform structure for three teams sharing a hub-and-spoke network. Review and debate it with Claude.

**Done when:** you can defend every decision against pushback.
